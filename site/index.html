Day 1 — Linux VM and Podman Setup

1. Finding the virtual machine IP address

This command displays the IP addresses assigned to the virtual machine. The IPv4 address is used for SSH and browser connections. 

hostname -I

2. Connecting through SSH

SSH provides remote terminal access to the Ubuntu Server. VS Code Remote SSH uses the same connection. 

ssh kon@192.168.110.137

3. Updating the package list

This command downloads current information about packages available from the Ubuntu repositories. 

sudo apt update

4. Installing Podman

Podman is the container engine used to download images, create containers and manage container resources. 

sudo apt install podman
podman --version

5. Starting the first Alpine container

This command creates an interactive container from the Alpine Linux image and opens its shell. 

podman run -it --name alpine-lab \
  docker.io/library/alpine:latest sh
run creates and starts a container -it opens an interactive terminal --name gives the container a readable name sh starts the Alpine command shell

6. Checking the operating system

This command was executed inside the container. It confirmed that the container was running Alpine Linux. 

cat /etc/os-release

7. Leaving and restarting the container

After leaving the shell, the container stopped. It could later be started again with the same name and filesystem. 

exit
podman ps -a
podman start -ai alpine-lab

Day 2 — Nginx Image and GitHub

1. Starting an Nginx web server

This command starts Nginx in the background and maps port 8080 on the virtual machine to port 80 in the container. 

podman run -d \
  --name web-test \
  -p 8080:80 \
  docker.io/library/nginx:alpine
-d runs the container in the background -p 8080:80 connects host port 8080 to container port 80

2. Checking running containers

This command displays active containers, their status, names, images and published ports. 

podman ps

3. Reading container logs

Logs show the Nginx startup process, HTTP requests and possible errors. 

podman logs web-test

4. Building a custom image

Podman reads the Containerfile from the current directory and creates version 1.2 of the website image. 

podman build --format docker \
  -t my-nginx-site:1.2 .
-t assigns a name and version tag to the image . uses the current directory as the build context

5. Running the custom website image

This creates a container from the image that contains the custom HTML page and Nginx configuration. 

podman run -d \
  --name my-site \
  -p 8080:80 \
  my-nginx-site:1.2

6. Inspecting Git changes

Git status shows changed files. Git diff shows the exact lines that were added, removed or modified. 

git status
git diff

7. Saving changes in Git

The files are added to the staging area and saved as a commit with a description. 

git add .
git commit -m "Update container project"

8. Uploading changes to GitHub

Git push sends local commits from the virtual machine to the connected GitHub repository. 

git push

Day 3 — Bind Mounts and Volumes

1. Viewing local images

This command displays downloaded and locally built images, including their tags, IDs and sizes. 

podman images

2. Removing an unused image version

An image can be removed when no container depends on it. The exact image name or ID identifies what should be removed. 

podman rmi my-nginx-site:1.0

3. Creating a bind mount

The local site directory is mounted directly into Nginx. Changes made in VS Code become visible after refreshing the browser without rebuilding the image. 

podman run -d \
  --name my-site-bind \
  -p 8081:80 \
  -v "$PWD/site:/usr/share/nginx/html:ro" \
  docker.io/library/nginx:alpine
$PWD/site is the site directory on the virtual machine /usr/share/nginx/html is the Nginx website directory :ro makes the mount read-only inside the container

4. Creating a named volume

A named volume stores persistent data managed by Podman. Its data can remain available after a container is removed. 

podman volume create nginx-site-data
podman volume ls

5. Using the named volume

The volume is mounted into the Nginx website directory. Port 8082 is used so this container can run together with the containers on ports 8080 and 8081. 

podman run -d \
  --name my-site-volume-new \
  -p 8082:80 \
  -v nginx-site-data:/usr/share/nginx/html \
  my-nginx-site:1.2

6. Executing a command inside a running container

Podman exec runs an additional command inside an existing container without creating a new container. 

podman exec my-site-volume-new \
  ls -l /usr/share/nginx/html

7. Checking all containers and port mappings

The -a option includes both running and stopped containers. The PORTS column shows which host port belongs to each container. 

podman ps -a
